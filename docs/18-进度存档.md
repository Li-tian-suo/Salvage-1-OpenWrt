## ⚠️ 重要更正：192.168.1.1 不是板子

这一点必须写清楚，否则下次又会走错方向。

**实测证据**：

```
arp -a  192.168.1.1  ->  MAC 68-de-ce-67-55-60
OUI 查询 68-DE-CE    ->  Fiberhome Telecommunication Technologies（烽火通信）
ttyd :7681 握手后显示 ->  "ponwrt login: "
```

**`192.168.1.1` 是一台烽火光猫。**

这台光猫上：
- `:80` 是它的管理页
- `:22` 是它的 SSH
- `:7681` 是它的 ttyd web 终端（不需要 token，但要 login）
- `:53` 是它的 DNS

**跟 HK09 板子没有任何关系。**

### 我怎么搞错的

之前板子跑着我们编的固件时，串口里显示的是：

```
root@LibWrt:~#
```

默认 IP 是 192.168.1.1，所以我就把 `192.168.1.1` 当成了板子。
但板子断电后，光猫占着同一个地址，我却在调查光猫——
试密码、扫端口、解析 ttyd 协议，全是无用功。

### 正确的做法

**先确认 MAC**：

```powershell
arp -a | Select-String '192.168.1.1'
```

- `68-de-ce-*` → 烽火（光猫）
- `00-03-7f-*` 或其他 → 可能是板子

**或者直接看串口** —— 串口不会骗人，`root@LibWrt:~#` 就是板子。

### 板子真正的连接方式

```
电脑 ──USB──> FTDI 串口（VID_0403 PID_6001）   给 COM6
电脑 ──网线──> 板子 lan1 口
板子 ──电源──> 独立供电
```

当前 FTDI 设备状态是 **`CM_PROB_PHANTOM`**（设备在物理上已移除），
必须拔插 USB 线才能恢复 —— 软件层面无法修复。
